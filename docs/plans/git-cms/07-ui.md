> **Built (2026-11-27):**

>   - a "Publish to" select (WordPress or any Git site; locked after the first send) and the readiness messages ("Finish Set up site…", "…needs attention");

## Connections (`connections-view.tsx`, Website section)

- **A new Git-based site card** next to WordPress, with the Sveltia/Decap icon.
  - States: not connected / connected / needs attention (see `05`).
  - Actions: Connect with GitHub, Use a token, Set up site, Check connection, Disconnect.
- **Set up site sheet** (`git-site-sheet.tsx`):
  - collection select;
  - field map table + front matter preview;
  - URL pattern + Test;
  - branch, commit as, deploy hook, site address;
  - Save.
  - At phone width it's a full-screen sheet and the table becomes stacked rows.
- **Repo picker page** (`/integrations/github/pick`): a list of the installation's repos, with a search box and a Continue button.

## Content settings (`content/settings`)

- **"Publish articles to":** a radio between WordPress (site + blog, as today) and Git site (repo + collection). Shown when both are connected; otherwise the connected one is used.
- **Git defaults:** author name, default tags.

## Article editor (`article-editor.tsx`), when the destination is a Git site

- **Destination** select at the top of the publish panel (when more than one site is connected; locked once sent).
- **Author:** text, shown only if the field map has an author field. "Author no." stays for WordPress.
- **SEO title and meta description** are written into the post through the field map.
  - The SEO paste step (`SeoPasteStep`) is hidden for Git sites.
  - If the site uses the excerpt as its meta description, the meta field says "Sent as the excerpt (the site's meta description)".
- **Front matter preview** (collapsible, monospace) and **URL preview** (`https://southafricasdr.com/blog/{slug}/`).
- **Tips** (`articleChecks()`, warnings only):
  - the slug is already used on the site;
  - an image is over 10 MB, or there are more than 20 images;
  - images from other websites will stay as links.
- **Buttons and confirm dialogs** use the site label instead of "WordPress": "Publish on southafricasdr.com now?", "Update on southafricasdr.com", "Delete from southafricasdr.com".

## Status (article header, lists, overview)

| State | Chip | Detail |
|---|---|---|
| scheduled | Scheduled | "Publishes {date time} ({zone}); live about a minute later" |
| publishing + waiting | Committed | Link to the commit on GitHub |
| publishing + building | Deploying… | Spinner; refreshes every 10 s while open |
| published + live | **Live** | Links: the post, the commit |
| failed + deploy failed | Deploy failed | Reason + build log link + **Retry** |
| failed (other) | Failed | Reason + Retry |
| conflict | Changed on the site | **Overwrite** / Cancel |

Lists and the client overview also get a destination badge (WordPress / the Git site's domain) and the live link.
